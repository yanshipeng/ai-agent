# 日志阅读指南（给新手）

> 目标：看懂服务在干什么，而不是被一堆 JSON 吓到。  
> 代码以仓库为准；本页讲「怎么读」。  
> 按周学习：[`week1_学习指南.md`](./week1_学习指南.md) · [`week2_学习指南.md`](./week2_学习指南.md)

## 1. 日志从哪来？

| 来源 | 怎么看 |
|------|--------|
| FastAPI 服务 | `./scripts/start_server.sh` 打到终端；建议 `tee` 存文件 |
| `requests.jsonl` | 每个请求一行**指标**（不是完整事件链） |
| 知识库脚本 | `scripts/build_*.py` 等用 **print 人话进度**（不是 JSON） |

推荐启动方式：

```bash
./scripts/start_server.sh 2>&1 | tee /tmp/app.log
```

另开终端发请求后，用 `request_id` 回放：

```bash
python scripts/trace_request.py <request_id> --log /tmp/app.log
```

## 2. 一行日志长什么样？

服务日志是**单行 JSON**，新手优先看：

| 字段 | 含义 |
|------|------|
| `event` | 英文事件名（可 `grep`） |
| `hint` | **中文说明**（专门给新手） |
| `request_id` | 同一次 `/ask` 的身份证 |
| `mode` | `llm` 直连模型 / `rag` 先检索再答 |
| `ts` | 时间（UTC） |

**不会**写入：用户问题原文、`DEEPSEEK_API_KEY`。  
问题只用 `query_len` + `query_sha256_8` 指纹关联。

## 3. 一条 `/ask` 会打出哪些事件？

### mode=llm（不查知识库）

```text
request_start      收到请求
llm_call_start     开始调 DeepSeek
llm_call_end       模型返回
request_success    整单成功（或 request_error 失败）
```

### mode=rag（本地知识库 + 模型）

```text
request_start      收到请求（hint 会写明是 rag）
retrieve_start     开始本地向量检索
retrieve_end       检索完成，已拼 Context（含 [1][2]…）
llm_call_start     带着 Context 调 DeepSeek
llm_call_end       模型返回
request_success    整单成功；带 retrieve_ms / citations_count
```

### 参数错误

```text
validate_failed → request_error
```

### 索引没建好（RAG）

```text
request_start → retrieve_start → request_error(INDEX_NOT_READY)
```

先跑：`python scripts/build_kb_index.py`

## 4. 和 `requests.jsonl` 的区别

| | 服务 JSON 日志 | `requests.jsonl` |
|--|----------------|------------------|
| 用途 | 看**过程**（检索了吗？模型重试了吗？） | 看**结果指标**（耗时、token、mode） |
| 条数 | 一次请求多行事件 | 一次请求一行 |
| 怎么读 | `trace_request.py` | `stats_requests.py` |

## 5. 三分钟实操

```bash
# 终端 A：起服务并存日志
./scripts/start_server.sh 2>&1 | tee /tmp/app.log

# 终端 B：打一条 RAG
curl -s 'http://127.0.0.1:8000/ask?mode=rag' \
  -H 'Content-Type: application/json' \
  -d '{"query":"Android ANR 怎么排查","top_k":5}' | tee /tmp/ask.json

# 取出 request_id 回放
RID=$(python -c "import json;print(json.load(open('/tmp/ask.json'))['request_id'])")
python scripts/trace_request.py "$RID" --log /tmp/app.log
```

你应能看到带中文 `说明:` 的 ①②③④⑤⑥ 步骤。

## 6. 知识库脚本日志（print）

这些不走 JSON，但开头会写清「在干什么」：

```bash
python scripts/build_stability_docs.py --no-refetch   # 清洗
python scripts/chunk_stability_docs.py                # 切块
python scripts/build_kb_index.py                      # 建索引
python scripts/retrieve_kb.py "ANR"                   # 只检索不调模型
```

流水线心智：

```text
articles → docs → chunks → index → retrieve → /ask?mode=rag → citations
```

## 7. 常见疑问

**Q：日志里没有 retrieve_start？**  
A：这次是 `mode=llm`，或看错了 `request_id`。

**Q：有 retrieve 但回答像瞎编？**  
A：用 `verify_ask_rag.py --response` 把 citations 对本地 index；日志只能证明「检索发生了」。

**Q：怎么确认没泄露 Key？**  
A：`trace_request.py` 发现 `sk-` / `"query":` 会报 `SENSITIVE LEAK`。
